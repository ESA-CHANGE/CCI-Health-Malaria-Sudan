# Malaria in Sudan and South Sudan

Analysis of malaria dynamics and their relationship with environmental and Earth Observation-derived information for the CHANGE UC5 Malaria case study in Sudan and South Sudan.

## Description

This repository contains the analysis code developed for the **CHANGE UC5 Malaria** case study.

The use case investigates malaria dynamics in Sudan and South Sudan and explores how Earth Observation and environmental information can support the analysis of malaria incidence, environmental suitability, forecasting, and associated uncertainty.

The repository does not reproduce the complete upstream processing chain from raw epidemiological and Earth Observation products. Instead, it provides analysis-ready processed datasets required to reproduce the main analytical workflows described below.

The analytical workflow is organised into three main components:

- **ESI** – comparison of malaria incidence with an EO-based Environmental Similarity Index;
- **Forecasting** – reproduction of the final EO-only M2 malaria forecasting model and its independent external validation;
- **Uncertainty** – propagation of Malaria Atlas Project (MAP) outcome uncertainty through the external evaluation of the final M2 model.

These components are developed as separate but related reproducible workflows within the repository.

## Getting Started

### Dependencies

The analyses are primarily implemented in **R**.

Dependencies differ between the ESI, forecasting, and uncertainty components. Requirements specific to each workflow are documented in the corresponding script directories.

Scripts are designed to use relative paths and should normally be executed from the root directory of the repository.

### Installing

Clone the repository:

```bash
git clone https://github.com/ESA-CHANGE/CCI-Health-Malaria-Sudan.git
```

Move to the repository directory:

```bash
cd CCI-Health-Malaria-Sudan
```

Install the R packages required by the analysis component that you intend to run.

Further information on component-specific dependencies and input data is provided in the corresponding directories.

The repository is organised as follows:

```text
.
├── data/
│   ├── esi/
│   ├── forecasting/
│   └── uncertainty/
├── scripts/
│   ├── esi/
│   ├── forecasting/
│   └── uncertainty/
├── results/
│   ├── esi/
│   ├── forecasting/
│   └── uncertainty/
├── README.md
└── LICENSE
```

## Executing the analyses

The main reproducible analyses are:

```text
scripts/esi/01_esi_analysis.R
scripts/forecasting/02_aoi_malaria_forecasting.R
scripts/uncertainty/03_map_outcome_uncertainty.R
```

Each script uses the processed input data distributed in the corresponding `data/` subdirectory and writes its outputs to the corresponding `results/` subdirectory.

Analyses should be run from the repository root so that relative paths to data and outputs remain consistent.

Component-specific `README.md` files provide details on:

- required input data;
- software dependencies;
- analysis parameters;
- execution workflow;
- outputs generated by each analysis.

## Input data

Processed input datasets required to run the published analyses are included in the corresponding `data/` subdirectories.

These datasets are derived from the original epidemiological and Earth Observation products used in the CHANGE UC5 Malaria case study and represent the analysis-ready inputs required by the scripts distributed in this repository.

The complete upstream workflow used to download, harmonise, resample, and preprocess the original source products is intentionally not reproduced here. Details on the content of each processed dataset are provided in the corresponding `data/*/README.md` files.

The repository therefore focuses on reproducibility of the selected analytical workflows rather than reproduction of the complete processing chain from raw source data.

## Help

Before running an analysis, check the corresponding component documentation under `scripts/` and `data/`.

Common issues may include:

- missing R packages;
- incorrect working directory;
- differences in local directory structure.

The repository root should normally be used as the working directory when executing analysis scripts.
